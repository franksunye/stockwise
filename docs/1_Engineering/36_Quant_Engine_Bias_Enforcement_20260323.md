# 36. Quant Engine Bias Enforcement (乖离率风控强制落地)

## 1. 背景与问题 (Context & Problem)
在近期的系统回顾与大模型基准测试日志（`LLM_Debug_Traces`）审查中发现：AI 分析师在输出判定结论时，为了解释其 `RiskOff` 决策的合理性，自发地多次运用了“乖离率（Bias）”这一量化概念（例如：“目前价格与 MA5 的乖离率尚未达到超跌反弹的极端值”）。

**漏洞暴露**：
经代码库全盘检索，**当前的底层物理预处理逻辑及大模型 System Prompt 中，压根未提供“乖离率”相关的显性变量计算或强制约束指令。** 
模型生成的内容完全基于其预训练学术语料的“知识涌现”。这严重违反了 ZISO 制定的**“死守 L2 级可解释系统规则”**的红线。依赖大模型自身的发散思维来进行风控（时有时无），属于倒退回了 L1 极度不可靠的玄学边缘。

## 2. 迭代目标 (Objective)
为贯彻“知行合一”，将前序整理在《01 量化分类学》里的“均值过滤”概念进行闭环落地。必须把“乖离率”从大模型的“自由发挥库”里抽离出来，变为一条强制物理规则和指令。

## 3. 具体实施方案 (Implementation Plan)

本次小型迭代将分为“物理预警”与“逻辑拦截”两步进行闭环：

### 实施点一：物理层数据前置计算（Data Pipeline Upgrade）
在执行模型调用的前置数据管道（如 `backend/scripts/run_min_tradeability_loop.py` 或相关策略分析脚本）中，插入乖离率特征计算。
*   **核心计算**：新增字段 `bias_ma20 = (Close - MA20) / MA20 * 100` 及短线 `bias_ma5`。
*   **物理报警**：设定绝对物理阈值（例如短线连续涨跌超 `10%~15%` 的严重偏离），一旦触发该极端值，附带高压报警标识 `Bias_Overheat` 送入 AI 的上下文数据 payload 中。

### 实施点二：Prompt 系统指令约束（Prompt Engineering）
升级 AI 核心分析师（如顾深/程矩）的系统级提示词模板。
*   **规则补充**：在防守/避险判断条款中，明确追加一条强制断路器（Circuit Breaker）指令。
*   **示例约束**：*“【强制安全锁】：当输入数据中检测到乖离率（Bias）标识处于超买或超跌极值状态时，无论当前均线与多空趋势如何强势，必须强制抑制你的做多/做空冲动，将其归组为高波动的震荡防守期。严禁在乖离率极端且未修复的状态下，执行右侧追涨或左侧摸底结论。”*

## 4. 结论 (Conclusion)
这项敏捷的小型工程迭代（Small Iteration），体现了 ZISO 将“主观或黑盒经验”持续萃取为“硬性 L2 工程代码规则”的治理哲学。不仅消灭了 AI 的自由裁剪与幻觉风险，也进一步稳固了我们向 C 端输出决议的胜率底线。
