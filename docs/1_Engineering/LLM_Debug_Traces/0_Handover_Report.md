## 1. 项目背景
由于线上 DeepSeek 模型在 2026-03-12 的分析中表现出一定的“趋势惯性”，我们对提示词进行了深度审计，发现其存在 **Token 冗余（单次 7000+）**、**职责错配**及**逻辑干扰**等问题。

## 2. 目录结构说明
- 📂 `prompts/`: 存放各阶段提示词模板。
    - `Baseline_Old_System/User.md`: 线上原始生产版本（对照组）。
    - `Shared_Optimized_System.md`: 基于架构解耦、Schema 上移后的通用系统提示词。
    - `B1_Minimal_User.md`: 极简版，仅包含衍生指标和 5 日 K 线。
    - `B2_Rich_User.md`: 完整版，包含 XML 封装的多周期 K 线流及预测历史。
    - `B3_Adversarial_System/Distilled_User.md`: 进阶博弈版，采用“趋势叙述”替代原始表格，执行双向博弈推理，当前仍属研究态。
    - `B4_STRICT_SYSTEM.md`: 四动作语义严格版，用于和 B2 做控制变量对比，不等同于已晋升生产模板。
- 📂 `results/`: 存放基准测试的 JSON 输出。
    - `samples/`: 存放 B2 与 B4 公平竞赛下的**原始响应明细** (JSON)。
    - `run_logs/`: 存放实验复跑日志。
- 📂 `scripts/`: 存放用于自动化对比测试的脚本。
    - `prompt_benchmarker.py`: 可重复执行的四方对比工具。
    - `test_layer1_impact.py`: 专门用于验证 Layer-1 注入对 AI 决策偏移的影响。
    - `fair_test_four_states.py`: 严谨的控制变量实验脚本，对比 3-State 与 4-State 的效率。

## 3. 核心发现与研究结论

### A. 架构重构胜过文字调整
*   **协议上移**：通过将 JSON Schema 定界符和验证规则从 `User` 移至 `System`，利用 **Prompt Cache** 特性，单次查询的输入 Token 从 7000+ 降至平均 2000-3000，**成本降低约 60%**。
*   **XML 封装**：使用 `<tags>` 替代复杂的 Markdown 表格，显著提升了模型对数据边界的识别能力。

> 审计补充：
> 这组结论在复跑中总体成立，但“协议上移”的价值应理解为方向性成立，不应把单次 token 数值当成固定常数。

### B. 历史数据的语义价值 (B2 vs B1)
*   **当前判断**：虽然精简版 (B1) 在 token 和时延上更优，但丰富版 (B2) 通常能提供更强的“多周期视野”。AI 在读到周线/月线表格后，更容易识别出“中期修正”等宏观信号，决策叙事也更完整。
*   **审计收口**：这说明 B2 具有潜在质量优势，但基于目前单 case 证据，**还不能把“生产环境必须保留 B2”写成硬结论**。更准确的表述应为：`B2 是当前质量优先路线的主候选，需要多 case 评估进一步验证。`

### C. 逻辑蒸馏的潜力 (B3)
*   **研究价值**：B3 证明了 AI 在处理“经过人类/后端提炼的趋势叙述”时，能够给出较强的逻辑压缩与博弈式表达。
*   **审计收口**：复跑结果不支持“B3 是极致速度最优解”这一说法。本轮复跑中，B3 没有达到 `<10s`，且 B1 比 B3 更快。同时，B3 再次出现结构退化（如 `tactics` 退化为字符串）的情况。
*   **当前结论**：`B3 值得继续作为“后端蒸馏输入”方向研究，但不应表述为当前生产最优解。`

### D. Layer-1 硬约束的必要性验证
*   **实验设计**：通过移除 B2 模板中的 `layer1_hard_constraints` 板块进行针对性压力测试。
*   **核心发现**：
    1.  **独立识别仍存在**：即便没有 L1 指令，基于优化后的 B2 数据结构，AI 依然会识别出破位风险。
    2.  **信心漂移显著**：移除 L1 后，AI 的自信度会明显升高，语气更具攻击性而非策略性。
    3.  **语义越权风险真实存在**：在复跑中，移除 L1 后模型直接产出了 `Short/Wait` 这类漂移枚举，而保留 L1 时会被压回系统允许的保守动作语义。
    4.  **价值确认为安全阀**：注入 L1 约束能有效引入“智性谦卑”，并降低模型越权输出风险，是保障系统一致性的关键安全阀。

### E. 信号语义升维的红利 (4-State Semantics)
*   **控制变量实验**：在保持所有 Schema 约束、Few-Shot 密度完全一致的前提下，对比 B2 (Legacy) 与 B4 (Strict)。
*   **核心发现**：
    1.  **决策消除歧义**：B4 能够利用 `RiskOff` 更精准地表达破位风险，而 B2 在 `Side` 语义下容易出现解释焦虑。
    2.  **语义收益成立**：四状态语义更贴近产品动作语言，这一价值在复跑中得到支持。
    3.  **性能红利未被稳定证明**：早期结果曾显示 B4 更省 token，但在复跑的公平对比中，`B4_STRICT_4_STATES` 并未稳定优于 `B2_OPTIMIZED_3_STATES`。
    4.  **当前结论**：`四状态的主要收益是语义对齐，不应直接表述为“已证明更省成本”。`

## 4. 后续工作建议 (Action Items)
1.  **模板合并**：将 `Shared_Optimized_System.md` 的核心逻辑合并至 `backend/templates/prompts/stock_analysis_system.j2`。
2.  **后端改造**：在 `prompts.py` 中，将周线/月线等大数据块改用 XML 标签包裹。
3.  **模式切换**：保留 `as_of_date` 作为基准日参数，但提示语义统一为“历史复盘模式 / 实时分析”，不再使用“请假装今天是”的回填式表达。
4.  **语义升级**：将后端 `SignalEnum` 及提示词指令从三阶（L/S/S）全面升级为产品定义的四阶动作语义（TriggeredLong, Watch, RiskOff, NoSetup）。
5.  **评估制度化**：在继续推进模板晋升前，补齐多 case eval runner，把“结构正确性、动作语义正确性、L1 对齐、token、latency”纳入统一评估。

## 5. 当前结论定位

截至本次修订，建议这样理解本目录中的各实验路线：

- `B1`：成本效率优先路线。
- `B2`：质量优先路线的主候选。
- `B3`：后端蒸馏输入研究路线，暂不应视为生产最优解。
- `B4/B4_STRICT`：四状态语义验证路线，已证明语义价值，但性能红利仍需更多样本验证。
