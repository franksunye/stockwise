# Master Series 极简生产规范

命名约定：

1. 对外栏目名默认使用 `交易大师图鉴`
2. 内部总线理解可使用 `交易经典图鉴`
3. repo 目录、文件名前缀、frontmatter 中继续保留 `master_series / ms`

适用范围：

- `docs/4_Growth_Ops/content/master_series/*.md`

目标：

- 稳定批量生产可长期复用的 `master_series`
- 面向中文读者
- 适合后续交给 `NotebookLM` 做 PPT / 信息图 / 音频

## 0. 文件结构

每个主题默认只保留 `2` 个文件，不要继续拆成三层或更多层。

固定结构：

1. `ms-xx_topic.md`
   - canonical 母稿
   - 给人看、给团队改、长期沉淀
2. `ms-xx_topic_notebooklm.md`
   - NotebookLM 输入稿
   - 只保留最适合被生成的短信息块

一句话：

**一个文件负责沉淀内容，一个文件负责喂给 NotebookLM。**

## 1. 内容定位

`master_series` 是长青知识内容，不是产品解释稿。

默认要求：

1. 不写我们自己如何吸收
2. 不写产品映射
3. 不写强转化尾巴
4. 先立人物和方法，再谈观点

一句话：

**先让读者觉得这个人真的牛，再让读者记住他真正留下了什么。**

## 2. 写作顺序

每篇默认按这个顺序组织：

1. 一句话先讲明白
2. 他是谁
3. 他为什么会让很多人佩服
4. 术语卡
5. 他最重要的三个核心观点
6. 代表方法 / 代表体系
7. 他解决了什么问题
8. 他不适合解决什么问题
9. 今天为什么还有这么多人反复讲他
10. 最后一句总结

补充要求：

1. 如果是`方法稿`，尽量补一句“它和相近方法的差别到底在哪”
2. 如果是`桥梁稿`，第一段就要讲清楚它是不是内部分层叫法，避免写成黑话

## 3. 人物稿的硬约束

### A. 必须有客观事实

至少补 `3` 类：

1. 战绩或代表性成绩
2. 代表作品 / 代表体系
3. 行业地位或传播影响

### B. 必须有数字

如果人物以实战著称，尽量落具体数字：

- 年度收益
- 比赛年份
- 代表性周期表现

不要只写：

- 很厉害
- 很传奇
- 很有影响力

### C. 必须中文优先

默认写法：

1. 首次出现：`中文名（英文名）`
2. 后文主叙述：用中文名或简称
3. 术语首次出现：中文 + 英文全称

不要在正文中段频繁切回英文姓氏。

## 3.0 每篇都要有“事实锚点”

不是每篇都必须有收益率和冠军数字，但每篇都必须有让读者信服的事实锚点，不能只剩理论和判断。

默认要求：

1. 人物稿：优先补`战绩 / 作品 / 体系 / 行业地位`
2. 方法稿：优先补`提出者 / 代表人物 / 经典归属 / 常见特征 / 典型应用场景`
3. 风险稿：优先补`它到底解决哪类老问题 / 常见对比对象 / 为什么会被反复使用`
4. 桥梁稿：优先补`它和哪些经典方法或人物直接相关 / 为什么不是空概念`
5. 事实来源优先级：`官网 / 出版社 / 书籍页 / 公开课程页` 优先于社区二手转述

一句话：

**人物靠数字和作品立住，方法靠出处和归属立住，风险靠问题与对比立住，桥梁靠和经典世界的连接立住。**

## 3.1 方法稿的硬约束

方法稿除了定义本身，还要尽量回答这两件事：

1. 它为什么会在经典路线里反复出现
2. 它和相近方法到底差在哪

默认目标：

**让读者不只是“知道这个名词”，而是知道它为什么不是别的名词。**

## 3.2 桥梁稿的硬约束

桥梁稿最容易写飘，默认要避免两种问题：

1. 写成产品说明书
2. 写成只有团队内部才懂的黑话

默认要求：

1. 第一段就说明这个概念是不是便于理解的分层叫法
2. 必须把抽象概念落回前面的人物、方法或系统
3. 要让没看过内部文档的读者也能接住

## 4. 术语写法

重要术语第一次出现时，默认这样写：

- `SEPA（Specific Entry Point Analysis，特定入场点分析）`
- `VCP（Volatility Contraction Pattern，波动收缩形态）`

术语卡的目标：

1. 帮中文读者接住英文行话
2. 显得专业
3. 不写成术语堆砌

## 5. 文风要求

默认文风：

1. 中文主叙述
2. 客观、克制
3. 有敬意，但不神化
4. 不写鸡汤
5. 不写产品腔

默认判断：

**人物可以被敬佩，但内容不能写成粉丝文。**

## 5.1 语言收口要求

在最终成稿阶段，要再过一遍“中文用户可读性”。

默认要求：

1. 尽量少用重复模板句
2. 少用一眼像 AI 批量生成的连接句
3. 优先用自然中文，而不是翻译腔中文
4. 同一个高频判断句，不要在多篇里机械重复

需要特别留意的句型：

1. `最重要的地方 / 真正重要的`
2. `把这些翻成人话`
3. `更稳的区分方式是`
4. `也就是说`

这些句型不是不能用，而是不能在整套系列里过度重复。

最终目标：

**让读者感觉是在读一个很会讲中文的作者，而不是在读一组统一模板。**

## 6. NotebookLM 交接要求

每篇都必须带可执行的交接区，不写抽象原理，只写步骤。

至少包含：

1. 第 1 步：整理精选交接包
2. 第 2 步：新建 notebook
3. 第 3 步：生成 `Presenter Slides`
4. 第 4 步：按 8 页结构检查
5. 第 5 步：不对就重生成
6. 第 6 步：再做信息图
7. 第 7 步：最后做音频
8. 第 8 步：人工复核

同时，每个主题都必须有一个单独的 `*_notebooklm.md` 输入稿。

## 6.1 `*_notebooklm.md` 固定结构

NotebookLM 输入稿默认固定为以下 `7` 个区块，顺序不要乱：

1. `人物身份`
2. `战绩数字` 或 `关键事实`
3. `关键术语`
4. `核心判断`
5. `生成硬约束`
6. `8 页页序`
7. `视觉线索`

说明：

1. 如果人物以比赛、收益或回报著称，用 `战绩数字`
2. 如果人物更以作品、体系和影响力著称，用 `关键事实`
3. 不要把长段解释塞进 `*_notebooklm.md`
4. 它不是文章摘要，而是生成输入稿

## 7. PPT 交接硬约束

默认要求：

1. 做成 `8` 页社媒型极简 PPT
2. 每页只承载 `1` 个核心信息点
3. 每页文字尽量控制在 `20-60` 字
4. 不要把一页做成小文章
5. 优先服务传播，不追求一次讲全

## 7.1 生成硬约束写法

每份 `*_notebooklm.md` 都必须有一段单独的 `生成硬约束`，默认至少写清楚这几条：

1. 做成 `8` 页中文社媒型极简 PPT
2. 每页只承载 `1` 个核心信息点
3. 每页文字尽量控制在 `20-60` 字
4. 不要把一页做成小文章
5. 重点放人物战绩 / 代表作品 / 代表体系 / 核心纪律 / 长期影响
6. 适合小红书、公众号配图、信息图传播
7. 强调高留白、大字号、快速识别

如果人物类型不同，第 `5` 条可以替换重点，但结构保持不变。

## 8. 精选交接包硬约束

默认只放：

1. 人物身份卡
2. 战绩卡
3. 术语卡
4. 一句话判断卡
5. 8 页页序卡
6. 视觉线索卡

在当前两文件制下，这些内容默认直接写进 `*_notebooklm.md`，不再单独拆第三个文件。

其中：

`8 页页序卡` 是硬约束。

要求：

1. 只写页标题
2. 不写长段解释
3. 不提前塞正文

## 9. 过稿检查

每篇完成前，至少自检这 6 条：

1. 有没有写清楚这个人为什么值得被记住
2. 有没有落至少一组关键数字
3. 有没有把英文变成中文读者能接住的表达
4. 有没有混入产品视角
5. 有没有把术语写准
6. NotebookLM 交接区是不是可以直接照着做

## 11. NLM 生产状态跟踪

为了在看板中清晰区分 NLM 的不同产出类型，每篇 canonical 母稿的 frontmatter 建议包含 `nlm_production` 块。

### A. Frontmatter 结构

```yaml
nlm_production:
  slides: "not_started"       # 演示文稿
  infographic: "not_started"  # 信息图
  audio: "not_started"        # 音频
  video: "not_started"        # 视频
```

### B. 状态取值范围

- `not_started`: ⚪ 未开始（默认）
- `generating`: 🔄 生产中
- `ready`: 🟢 已完成
- `approved`: ✅ 已通过

### C. 看板显示规则

1. 脚本会自动统计四类产出的完成比例
2. 在 `NLM 生产状态` 专表中，每篇稿件的四类产出将以 Emoji 形式并排显示
3. 如果 frontmatter 中缺失该块，脚本将自动默认为 `not_started`

一句话：

**母稿管深度，输入稿管效率，nlm_production 管多模态产出落地。**
