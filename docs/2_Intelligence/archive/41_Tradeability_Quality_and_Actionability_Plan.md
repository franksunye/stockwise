## 1. 阶段定位

`Plan 40` 已完成 Layer-1 / Layer-2 双层架构重构、策略版本化、历史回灌与窗口观测闭环。

`Plan 41` 不再解决“架构是否成立”，而是解决三个更接近产品落地的问题：

1. `tradeability_v2` 是否能从“更积极”进化到“收益质量更好”。
2. `RiskOff / Watch / TriggeredLong / NoSetup` 是否能稳定翻译成普通投资者可执行的动作语言。
3. 本地研究结论是否能够通过线上 sidecar 影子运行得到验证。

### 1.1 业务目标（本计划的商业含义）

知守 AI (ZISO AI) 在该阶段的业务目标，不是单纯“把量化模型跑起来”，而是形成一条可持续的自动化闭环：

1. 在线上持续自动运行实验。
2. 自动积累真实市场样本，而不是长期依赖手工研究样本。
3. 在研究链路中持续比较版本优劣，找到更好的量化模型与参数组。
4. 只将通过验证的更优版本推向生产链路。
5. 最终向用户持续提供“更好的量化 + AI 工具能力”，而不是一次性的策略发布。

因此，`Plan 41` 的本质不是单点调参，而是建设一套 `research -> validate -> promote -> serve users` 的长期机制。

### 1.2 本计划所在层级

该议题应落在 `2_Intelligence` 主文档，而不是仅落在 runbook 或产品定位文档，原因如下：

1. 它不是单纯的品牌叙事，而是研究与生产之间的核心方法论。
2. 它不是某个 workflow 的局部说明，而是指导后续自动化实验和生产升级的总执行口径。
3. 它直接决定：
   - 实验链路如何定义成功
   - 生产链路如何定义升级门槛
   - 用户最终看到的能力是否持续变好

### 1.3 当前策略类型与研究边界

为避免后续研究跑偏，必须先固定当前 tradeability 的策略类型：

1. 当前核心属于**趋势突破型**量化，不是均值回归型。
2. 当前核心依赖：
   - 收缩/结构准备
   - 放量突破
   - 动量修复
   - 风险否决
3. 当前研究目标不是“尽可能多地产生信号”，而是让：
   - `Watch -> TriggeredLong` 更有质量
   - `RiskOff` 更合理
   - 最大回撤更可控
   - 产品层结果更完整、更稳定

结论：

**Plan 41 研究的是“更好的出手决策链路”，不是抽象的全能量化。**

## 3. 阶段目标

### 3.1 收益质量目标

1. 不以进一步抬高 `TriggeredLong coverage` 为优先目标。
2. 优先优化：
   - `Watch -> TriggeredLong` 转化质量
   - `RiskOff` 占比
   - 最大回撤
   - 单位交易的有效性

### 3.2 产品动作化目标

将 Layer-1 状态稳定映射为普通投资者可执行动作：

1. `TriggeredLong -> 可尝试建仓`
2. `Watch -> 继续观察`
3. `RiskOff -> 暂停新增仓位 / 已有仓位应收缩`
4. `NoSetup -> 不建议出手`

要求：

1. 映射口径固定，不因模型输出风格漂移。
2. 不改前台大结构，仅改输出文案与战术表达。

### 3.2.a 面向未来策略产品层的约束

`Plan 41` 的产出，不只是为了把 `tradeability_v2` 调得更顺手，也是在为未来的“策略产品层”打底。

约束如下：

1. 后台允许继续扩展多版本、多策略族与多市场适配。
2. 但当前阶段对外仍只暴露统一动作语言，不把裸策略参数直接抛给普通用户。
3. 后续如果形成“稳健型 / 平衡型 / 进取型 / 防守模式”等模式商店，其底层也必须建立在当前这套 Layer-1 状态机、收益质量评估与动作语言映射之上。

### 3.3 线上验证目标

1. 将当前 `v2` 基线作为实验版本持续 sidecar 并行观察。
2. 验证本地研究结论是否与线上连续样本一致。
3. 在满足 `39` 中 `v2 Default Promotion Gate` 前，不切默认版本。

## 4. 执行顺序

### Step 1: 冻结当前 `v2` 基线

目标：

1. 将当前参数组视为标准比较点。
2. 在没有明确证据前，不再做大幅参数漂移。

验收：

1. 所有后续实验都以当前 `v2` 参数为 baseline。

### Step 2: 收益质量导向微调

调优原则：

1. 每轮只改 1 个参数。
2. 优先参数：
   - `vcp_ratio`
   - `strong_close_threshold`
   - 其次才是 `risk_off_ma`
3. 不再优先放宽 `breakout_volume_mult / momentum_change_threshold`。

观测指标：

1. `TriggeredLong coverage`
2. `Watch -> TriggeredLong`
3. `RiskOff` 占比
4. `Max Drawdown`
5. `100万` 起始资金的资金曲线结果

### Step 3: 动作语言固化

目标：

1. 保证 summary 和 tactics 的用户语言与 Layer-1 状态一致。
2. 让普通投资者看到的是“该不该出手 / 该不该收手”，而不是纯策略术语。

验收：

1. 所有模型输出都通过统一映射层收口。
2. `rule-engine` 与 LLM synthesis 的动作语言一致。

### Step 4: 线上 sidecar 影子观察

目标：

1. 持续积累线上 `quant_tradeability_signals`。
2. 验证本地 `499` 样本下的结论是否在真实运行中保持稳定。

验收：

1. 至少连续 `2~4` 周可观察历史。
2. 满足 `39` 的默认切换门槛前，不进入默认替换。

## 5. 当前决策

当前阶段结论如下：

1. `tradeability_v2` 保留为下一阶段主研究版本。
2. `tradeability_v1` 继续保留为保守基准版本。
3. 下一阶段不再回答“架构对不对”，而回答“用户能不能据此做动作，以及收益质量能不能提升”。

## 5.1 自动化研究到生产的闭环定义

为对齐业务目标，后续所有相关工作都应按以下闭环理解，而不是把“研究”和“生产”看成两套孤立动作。

### A. Research Quant Lane

职责：

1. 自动扩充样本。
2. 自动运行 sidecar。
3. 自动做 weekly calibration / version comparison。
4. 自动评估实验版本是否优于当前生产基线。

目标：

1. 持续找到候选更优版本。
2. 形成可复验、可审计、可对比的研究证据。

### B. Production Decision Lane

职责：

1. 向用户提供正式、稳定、可解释的结果。
2. 只消费已经通过验证的版本或模式口径。
3. 保持用户侧输出稳定，不让实验漂移直接污染正式展示。

目标：

1. 持续为用户提供更好的正式能力。
2. 在升级时做到“更优版本进入生产”，而不是“最新版本直接进入生产”。

### C. 闭环原则

1. `Research Quant Lane` 负责产生候选最优解。
2. `Production Decision Lane` 负责承接已验证的最优解。
3. 升级条件必须基于效果数据，而不是基于主观感受或单周表现。
4. 若研究效果没有显著优势，则不推进生产升级。

## 5.2 四象限指标框架

后续看板、周报、验收都必须区分四类指标，禁止再用一句“数据怎么样”混在一起讨论。

### A. Production Ops

回答：

1. 生产链路有没有正常产数。
2. 用户正式数据有没有延迟、失败、缺口。

示例指标：

1. daily pipeline 成功率
2. mode pipeline 成功率
3. 最新产出日期
4. 正式结果覆盖率

### B. Production Effect

回答：

1. 当前给用户看的正式结果是否稳定有效。

示例指标：

1. `mode_performance_snapshot` 的 hit rate
2. max drawdown
3. payoff ratio
4. stability score
5. sample size

### C. Research Ops

回答：

1. 研究链路有没有按计划自动运行。
2. sidecar / sample sync / calibration 是否持续积累证据。

示例指标：

1. sample sync 成功率
2. sidecar 最新日期覆盖
3. calibration 最近运行时间
4. 研究样本规模

### D. Research Effect

回答：

1. 实验版本是否真的优于当前生产基线。

示例指标：

1. `quant_tradeability_signals` 状态分布
2. `TriggeredLong coverage`
3. `RiskOff` 占比
4. `Watch -> TriggeredLong` 转化
5. v1 / v2 / future_v3 对比
6. default promotion gate 达标情况

### E. 管理规则

1. `Ops` 指标解决“有没有跑”。
2. `Effect` 指标解决“跑出来的东西好不好”。
3. 只有 `Research Effect` 持续优于当前生产基线时，才允许讨论推进生产。
4. 只有 `Production Effect` 稳定时，才说明用户真正受益。

## 6. 退出条件

当以下任一条件满足时，可认为 `Plan 41` 完成：

1. `v2` 在收益质量上明显优于当前基线，并通过线上影子观察。
2. 动作语言已在线上/前台口径稳定运行，且不再依赖模型自由措辞。
3. 项目已形成是否允许 `v2` 切默认的正式决策结论。

## 7. 终局导向（对业务目标的直接对齐）

当本计划推进到成熟阶段，知守 AI (ZISO AI) 应具备以下能力：

1. 自动做实验，而不是人工零散试验。
2. 自动筛选更优量化版本，而不是凭感觉决定升级。
3. 自动把通过验证的更优版本推向生产，而不是长期停留在研究环境。
4. 让用户持续获得更强的量化 + AI 决策辅助能力。

这也是本计划最核心的商业意义：

我们不是在维护一套静态模型，而是在建设一台持续进化、持续把更优能力输送给用户的产品机器。
