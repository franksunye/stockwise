# StockWise 交易方法与大师智慧的研究吸收框架

**文档状态**: Current Strategy  
**日期**: 2026-03-12  
**作者**: Codex  
**用途**: 统一回答一个顶层问题  
当我们面对海龟交易法、埃尔德、巴菲特、芒格、威廉欧奈尔、Minervini、达利欧等方法与人物时，StockWise 应该如何系统吸收，而不是随意拼贴。

---

## 1. 这份文档解决什么问题

StockWise 后续一定会不断遇到这类问题：

1. 某个交易方法值不值得纳入？
2. 某位大师的思想应该归到哪里？
3. 哪些可以进入后台研究？
4. 哪些可以变成正式模式？
5. 哪些只能作为解释层、风控层、研究约束，而不能直接上线？

如果没有统一框架，团队会很容易陷入三种混乱：

1. 把“名气”误当成“可产品化能力”
2. 把“哲学”误当成“规则”
3. 把“局部技巧”误当成“完整系统”

所以这份文档的核心任务只有一句话：

**建立一个面向 StockWise 的方法吸收、扩展、筛选、上线框架。**

---

## 2. 先给结论

### 2.1 不是所有“大师智慧”都应该进入同一层

StockWise 不应把所有方法和人物都当成“一个新策略”。

更合理的做法是：

把它们拆成不同层级吸收。

### 2.2 我们需要的不是“策略收藏夹”，而是“方法操作系统”

如果未来只是不断新增：

1. 海龟模式
2. 埃尔德模式
3. 巴菲特模式
4. 欧奈尔模式

系统会很快失控。

StockWise 真正需要的不是“名人模式库”，而是：

**一套能把外部方法拆解、映射、评估、试验、收敛的操作系统。**

配套案例集见：

- [`07_Method_To_StockWise_Semantic_Mapping_Examples.md`](/Users/yesun/Code/stockwise/docs/0_Strategy/07_Method_To_StockWise_Semantic_Mapping_Examples.md)

### 2.3 最重要的原则

所有外部方法与大师思想，进入 StockWise 前都必须先回答：

1. 它属于哪一层？
2. 它能否被量化？
3. 它适不适合 C 端动作语义？
4. 它应该进入研究线、解释层、风控层，还是正式模式？

## 3. 顶层模型：外部方法进入 StockWise 的六层框架

StockWise 应该把外部方法拆成六层：

### L1 世界观层

回答：

- 我们到底相信什么样的市场规律？

典型内容：

1. 趋势会延续，还是价格会回归均值？
2. 市场先生是否会长期错误定价？
3. 风险的本质是波动、回撤，还是永久损失？
4. 投资是博弈、配置，还是企业所有权判断？

这一层更接近：

- 巴菲特
- 芒格
- 达利欧
- 索罗斯

这一层通常**不能直接写成单条交易规则**。

它的作用是：

- 决定 StockWise 接受什么，不接受什么

### L2 研究原则层

回答：

- 我们应该如何研究、如何控制错误？

典型内容：

1. 不预测噪音，优先看大结构
2. 风险优先于收益
3. 不做没有样本外支撑的优化
4. 不做无法解释的黑箱承诺
5. 不让单笔亏损失控

这一层更像：

- 方法纪律
- 风险哲学
- 研究守则

它通常不直接出信号，但会决定：

- 哪些方法有资格进实验

### L3 策略原型层

回答：

- 这套方法在交易逻辑上属于哪一类母策略？

典型原型：

1. 趋势跟随
2. 突破交易
3. 均值回归
4. 价值发现
5. 质量成长
6. 事件驱动
7. 组合配置

这一层是最关键的中间层。

因为海龟、欧奈尔、Minervini、Darvas 这些东西，很多时候不该以“人名”进入系统，而应该先映射成：

- 趋势突破原型
- 波动止损原型
- 质量成长筛选原型

### L4 规则组件层

回答：

- 具体有哪些可组合、可测试、可替换的规则零件？

例如：

1. Donchian breakout
2. ATR stop
3. moving average filter
4. volume expansion
5. relative strength
6. earnings growth filter
7. valuation guardrail
8. position sizing rule

这一层才是后台研究最该工程化的层。

### L5 投资模式层

回答：

- 同一套底层分析，在不同用户风格下应如何裁决与执行？

典型内容：

1. 稳健
2. 平衡
3. 进取
4. 仅观察

这一层不是“分析市场的方法”，而是：

- 用户动作风格层
- 决策风格层
- 产品封装层

这意味着：

- 海龟、MACD、网格、欧奈尔、Minervini 都不应直接进入这一层
- 这一层输出的是“用户如何行动”，不是“市场本质是什么”

### L6 视图表达层

回答：

- 最终用户应该看到什么？

StockWise 当前已经明确：

1. 四语义：
   - 建议进场
   - 建议观察
   - 建议防守
   - 暂无信号
2. 模式层：
   - 稳健
   - 平衡
   - 进取
   - 仅观察

这意味着：

- 外部方法不应该直接覆盖产品语义层
- 产品层最终仍然要统一翻译成 StockWise 自己的语言
- 同一后台事实，在首页、内参、决议页可以有不同展示重心

## 3.1 与当前产品/工程模型的对应关系

为了避免未来把“方法”“模型”“模式”混在一起，当前统一采用以下映射：

| 研究框架层 | 对应系统概念 | 说明 |
| --- | --- | --- |
| `L1 世界观层` | 世界观 / 研究前提 | 决定我们接受什么市场认知 |
| `L2 研究原则层` | 研究守则 / 风险纪律 | 决定哪些方法有资格进入研究线 |
| `L3 策略原型层` | 量化方法框架 | 例如趋势跟随、突破、均值回归、网格、价值、配置 |
| `L4 规则组件层` | 量化规则组件 | 例如 Donchian、ATR、MA filter、volume expansion |
| `L4 规则组件层 + 状态机收敛` | 量化模型 | 当前工程实现对应 `QuantEngine / Layer-1` |
| `LLM 解释层` | 分析模型 | 负责 AI 判断、解释、战术展开 |
| `L5 投资模式层` | 投资模式 | steady / balanced / aggressive / observe-only |
| `L6 视图表达层` | 视图层 | 首页、策略内参、投资决议页的展示选择 |

其中最关键的命名边界是：

1. 海龟、MACD、网格、欧奈尔，不是“投资模式”
2. 它们属于量化方法框架或量化规则组件
3. `Layer-1` 是当前量化模型的实现层名，不应直接等同于所有未来方法体系
4. `投资模式` 只负责用户动作风格，不负责定义研究方法本身

如果要看具体案例如何落位，参考：

- [`07_Method_To_StockWise_Semantic_Mapping_Examples.md`](/Users/yesun/Code/stockwise/docs/0_Strategy/07_Method_To_StockWise_Semantic_Mapping_Examples.md)

## 4. 一切外部方法，先做三种拆解

任何方法进入 StockWise，先不要问“好不好”，先问“它是什么”。

必须做三种拆解：

## 4.1 拆成“道”

也就是：

- 它的底层信念是什么？

例如：

1. 海龟：
   - 趋势可跟随
   - 突破值得追随
   - 风险控制比预测更重要
2. 埃尔德：
   - 多周期比单周期更可靠
   - 风险与心理纪律优先
3. 巴菲特 / 芒格：
   - 企业质量、护城河、资本配置能力比短线波动更重要
   - 风险是永久资本损失

## 4.2 拆成“法”

也就是：

- 它的方法纪律是什么？

例如：

1. 海龟：
   - 统一止损
   - 统一加仓
   - 统一资金风险单位
2. 埃尔德：
   - 先看大周期方向
   - 再看小周期触发
   - 账户风险必须受控
3. 巴菲特 / 芒格：
   - 先筛掉烂生意
   - 不做看不懂的东西
   - 不因为波动而强行交易

## 4.3 拆成“术”

也就是：

- 它有哪些具体可测试组件？

例如：

1. 海龟：
   - Donchian breakout
   - ATR stop
   - pyramid add-on
   - volatility sizing
2. 埃尔德：
   - Triple Screen
   - momentum oscillator timing
   - trend filter + trigger split
3. 巴菲特 / 芒格：
   - ROE / ROIC / cash flow quality filters
   - leverage guardrails
   - valuation bands

## 4.4 方法进入系统后的标准落位

为了让未来扩展不失控，任何外部方法在进入 StockWise 时，都应先落位到以下四类对象之一：

> [!NOTE]
> **判定基石**：所有方法的验证与执行分离逻辑应遵循 [05 量化信号验证与执行公理](../0_Strategy/05_Quant_Signal_and_Execution_Axioms.md)。

### 4.4.1 量化方法框架

适合放这里的内容：

- 趋势跟随
- 突破交易
- 均值回归
- 网格交易
- 价值发现
- 质量成长
- 组合配置

这一层回答的是：

- 这类方法在交易逻辑上属于什么母类

### 4.4.2 量化规则组件

适合放这里的内容：

- Donchian breakout
- ATR stop
- moving average filter
- volume expansion
- relative strength
- valuation guardrail
- position sizing rule

这一层回答的是：

- 具体哪些零件能进入量化模型

### 4.4.3 分析模型提示与解释框架

适合放这里的内容：

- 哪些方法适合成为 LLM 的解释词汇
- 哪些适合成为 AI 的对照视角
- 哪些只适合作为战术解释，不适合变成主信号规则

### 4.4.4 投资模式

只有在以下问题成立时，才进入投资模式层：

1. 它面对的是用户动作风格差异
2. 它不是在定义市场识别方法
3. 它是对同一底层事实的不同裁决方式

所以：

- “稳健 / 平衡 / 进取 / 仅观察”属于投资模式
- “海龟 / MACD / 网格 / Triple Screen”不属于投资模式

## 5. StockWise 里的归属框架：它到底该放哪

这是最关键的一部分。

任何外部方法，只能进入以下六种归属之一：

## A. 世界观约束

作用：

- 决定系统长期不做什么、优先做什么

适合纳入：

- 巴菲特
- 芒格
- 达利欧的部分风险思想

例子：

1. 不做纯高频
2. 不用黑箱承诺收益
3. 风险控制优先于进攻炫技

## B. 研究原则

作用：

- 约束实验方法，而不是直接产出用户信号

适合纳入：

- 埃尔德的风险纪律
- 海龟的资金纪律
- 机构量化的样本外纪律

例子：

1. 单笔风险上限
2. 正式 search audit
3. 样本外先于样本内

## C. 策略原型

作用：

- 成为 Research Quant Lane 的母策略家族

适合纳入：

- 海龟
- 欧奈尔
- Minervini
- Darvas
- 价值 / 质量 / 均值回归等母策略

例子：

1. `trend_breakout_archetype`
2. `quality_growth_archetype`
3. `value_guardrail_archetype`

## D. 规则组件

作用：

- 成为可插拔、可组合、可回测的引擎部件

适合纳入：

- ATR stop
- Donchian breakout
- MA filter
- RS filter
- valuation ceiling

这是最适合工程化沉淀的层。

## E. 解释框架

作用：

- 不直接决定入场规则，但决定“如何向用户说明”

适合纳入：

- 埃尔德
- 芒格
- 霍华德马克斯

例子：

1. 多周期解释
2. 风险优先解释
3. 心理纪律提示
4. 为什么此时应等待而不是冲动出手

## F. 正式产品模式

作用：

- 面向用户可选的投资模式

适合纳入的不是“人名”，而是：

- 风险风格与动作密度

所以正式模式应继续保持：

1. 稳健
2. 平衡
3. 进取
4. 仅观察

而不是：

1. 海龟模式
2. 巴菲特模式
3. 埃尔德模式

这是一个非常重要的产品边界。

## 6. 选择框架：一个方法值不值得纳入

任何方法进入 StockWise，都要先通过 8 个问题。

## 6.1 八问模型

1. **产品目标一致吗？**
   - 它最终能不能帮助普通投资者做更好的动作决策？
2. **可量化吗？**
   - 能不能拆成规则、指标、约束或可验证逻辑？
3. **可解释吗？**
   - 能不能被翻译成用户听得懂的话？
4. **数据可得吗？**
   - 当前数据底座是否支持？
5. **回测可验证吗？**
   - 能否在研究线形成清晰证据？
6. **现实可执行吗？**
   - 是否受成交、容量、时间尺度限制过强？
7. **能融入现有语义吗？**
   - 能否最终回到“进场 / 观察 / 防守 / 暂无信号”？
8. **引入复杂度值得吗？**
   - 带来的增量价值，是否大于系统复杂度的上升？

## 6.2 五档结论

每次评估一个方法，最终只能给五种结论：

1. **Reject**
   - 不适合 StockWise
2. **Inspiration Only**
   - 只吸收思想，不进入规则
3. **Research Only**
   - 进入研究线，不进生产线
4. **Shadow / Overlay**
   - 可进入影子观察或解释层
5. **Production Candidate**
   - 具备进入正式模式治理的资格

## 7. 扩展框架：以后越来越多方法，系统怎么不乱

为了避免未来失控，StockWise 应采用“方法注册表”思路。

## 7.1 每个新方法都必须有一张 Method Card

最少字段：

1. 名称
2. 来源
3. 所属层级
4. 母策略类型
5. 核心原则
6. 可量化组件
7. 数据要求
8. 风险
9. 建议归属
10. 当前状态

## 7.2 当前状态只能选一个

1. `parked`
2. `researching`
3. `baseline`
4. `shadow`
5. `production_candidate`
6. `adopted_principle`
7. `rejected`

## 7.3 不允许直接从“看到一个大师”跳到“上线一个模式”

标准路径必须是：

1. 方法识别
2. 拆解成道法术
3. 归属判定
4. 研究线验证
5. shadow / overlay 观察
6. 才能讨论是否进入正式模式

## 8. 用这个框架看几个典型例子

## 8.1 海龟交易法

### 归属判断

1. 世界观：
   - 趋势跟随
2. 研究原则：
   - 风险单位化
3. 策略原型：
   - breakout trend-following
4. 规则组件：
   - Donchian breakout
   - ATR stop
   - pyramiding
   - volatility sizing
5. 产品模式：
   - 不建议直接做“海龟模式”

### 结论

- `Research Only` 或 `Baseline`

## 8.2 埃尔德

### 归属判断

1. 世界观：
   - 多周期更可靠
2. 研究原则：
   - 风险优先
3. 策略原型：
   - multi-timeframe trend + trigger
4. 规则组件：
   - trend filter + timing trigger split
5. 解释框架：
   - 非常适合
6. 产品模式：
   - 不建议直接做“埃尔德模式”

### 结论

- `Adopted Principle + Overlay`

## 8.3 巴菲特 / 芒格

### 归属判断

1. 世界观：
   - 企业质量、护城河、资本配置、长期赔率
2. 研究原则：
   - 不做看不懂的东西
   - 风险是永久损失
3. 策略原型：
   - quality / value discipline
4. 规则组件：
   - 可转译为质量筛选、杠杆约束、估值护栏
5. 解释框架：
   - 很适合做“为什么不出手”的解释
6. 产品模式：
   - 绝不建议直接做“巴菲特模式”

### 结论

- `Inspiration Only` 到 `Research Principle`

## 9. 对 StockWise 后台研究与上线优化的真正含义

这套框架落到工程上，意味着三件事：

## 9.1 后台研究不再以“名人”为中心

不再问：

- 要不要做海龟？
- 要不要做巴菲特？

而是问：

1. 我们是否要引入“趋势突破原型”？
2. 我们是否要引入“多周期过滤原则”？
3. 我们是否要引入“质量筛选护栏”？
4. 我们是否要引入“ATR 风险控制组件”？

这会让系统从“人物崇拜式扩展”变成“模块化扩展”。

## 9.2 正式上线优化不再以“新模式”作为默认输出

不是每吸收一个方法，就新增一个用户模式。

大多数外部方法，应优先进入：

1. 研究基线
2. 规则组件库
3. 风险纪律层
4. AI 解释层

只有少数真正能改善：

1. 模式稳定性
2. 用户动作语义
3. 产品分层

的东西，才值得进入正式模式治理。

## 9.3 顶层设计要坚持“外部方法内化，用户语义统一”

这句话最重要：

**外部方法可以很多，但用户语言必须很少。**

后台可以吸收：

1. 海龟
2. 埃尔德
3. 巴菲特
4. 欧奈尔
5. Minervini
6. 达利欧

但前台仍然应该稳定为：

1. 模式层
   - 稳健 / 平衡 / 进取 / 仅观察
2. 动作层
   - 进场 / 观察 / 防守 / 暂无信号

这就是系统复杂度与产品简洁度之间最关键的平衡。

## 10. 最终框架

用一句话总结：

**StockWise 不应该把外部方法和大师智慧，当成“一个个待上线的新模式”；而应该把它们拆成世界观、研究原则、策略原型、规则组件、解释框架，再通过统一的筛选与归属机制吸收。**

再压缩成一句更短的话：

> 人物不直接进产品，  
> 方法先拆成层，  
> 组件先入研究线，  
> 只有通过筛选的能力，才有资格进入正式模式。
