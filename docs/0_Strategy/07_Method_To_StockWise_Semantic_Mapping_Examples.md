# StockWise 方法到内部语义的典型映射案例

**文档状态**: Current Strategy  
**日期**: 2026-03-13  
**用途**: 用典型案例说明，外部方法/大师思想如何映射到 StockWise 内部语义体系

---

## 1. 目的

本文档不是介绍这些方法本身，而是回答一个更重要的问题：

**当 StockWise 遇到一个外部方法时，应该把它落到哪一层？**

这是一份抽象建模样例集，用来避免以下混乱：

1. 把方法误叫成投资模式
2. 把研究原则误当成规则组件
3. 把执行策略误当成量化模型
4. 把大师名字直接搬进产品层

---

## 2. 当前统一语义框架

后续所有映射统一使用以下层级：

1. 世界观层
2. 研究原则层
3. 量化方法框架
4. 量化规则组件
5. 量化模型
6. 分析模型
7. 投资模式
8. 视图层

其中：

- `Layer-1` 是当前量化模型的工程实现层名
- 不是未来所有方法体系的总称

---

## 3. 案例一：巴菲特

### 3.1 它是什么

巴菲特首先是一套：

- 长期价值投资世界观
- 质量与资本配置优先的研究体系

### 3.2 它不是什么

巴菲特不是：

- 投资模式
- 分析模型
- 单一交易信号方法

### 3.3 在 StockWise 中的落位

| 层级 | 映射判断 |
| --- | --- |
| 世界观层 | 强映射 |
| 研究原则层 | 强映射 |
| 量化方法框架 | 中映射，主要对应价值发现 / 质量成长 |
| 量化规则组件 | 弱到中映射，需要进一步抽象 |
| 投资模式 | 不直接映射 |

### 3.4 如何进入系统

巴菲特不应以“巴菲特模式”进入系统，而应拆成：

1. 研究前提
   - 风险是永久损失
   - 企业质量优先于短期波动
2. 原型
   - 价值发现
   - 质量成长
3. 组件
   - ROE / ROIC
   - 现金流质量
   - 杠杆约束
   - 估值安全边际

### 3.5 最终产品表达

巴菲特思想不会直接变成一个用户模式。  
它更适合：

- 约束研究方向
- 形成价值/质量类量化方法框架
- 让分析模型在解释层使用“企业质量 / 安全边际”语言

---

## 4. 案例二：埃尔德

### 4.1 它是什么

埃尔德是一套更接近可执行交易系统的方法：

- 多周期确认
- 趋势过滤
- 触发分离
- 风险纪律

### 4.2 它不是什么

埃尔德不是：

- 投资模式
- 单一指标
- 单纯哲学层人物

### 4.3 在 StockWise 中的落位

| 层级 | 映射判断 |
| --- | --- |
| 世界观层 | 中映射 |
| 研究原则层 | 强映射 |
| 量化方法框架 | 强映射，主要对应趋势跟随 / 触发确认 |
| 量化规则组件 | 强映射 |
| 投资模式 | 不直接映射 |

### 4.4 如何进入系统

埃尔德适合拆成：

1. 原则
   - 先看大周期，再看小周期
   - 风险优先
2. 原型
   - 趋势跟随
   - 多周期确认
3. 组件
   - 大周期趋势过滤
   - 小周期触发
   - 动能确认
   - 止损纪律

### 4.5 最终产品表达

埃尔德不应成为“埃尔德模式”，而更适合成为：

- 量化模型中的趋势/触发类规则来源
- 分析模型的解释词汇来源

---

## 5. 案例三：海龟交易法

### 5.1 它是什么

海龟交易法是一套高度规则化的趋势跟随系统。

其特点是：

- 规则明确
- 触发明确
- 止损明确
- 资金管理明确

### 5.2 它不是什么

海龟交易法不是：

- 投资模式
- 纯世界观
- 页面展示语言

### 5.3 在 StockWise 中的落位

| 层级 | 映射判断 |
| --- | --- |
| 世界观层 | 中映射 |
| 研究原则层 | 强映射 |
| 量化方法框架 | 强映射，主要对应趋势跟随 / 突破交易 |
| 量化规则组件 | 很强映射 |
| 投资模式 | 不直接映射 |

### 5.4 如何进入系统

海龟最适合被拆成组件进入量化模型：

1. Donchian breakout
2. ATR stop
3. pyramiding
4. volatility sizing

### 5.5 最终产品表达

海龟不应以“海龟模式”面向用户。  
它应以：

- 突破类量化方法框架
- 趋势跟随类规则组件

的方式进入后台，再由产品统一翻译成：

- 建议进场
- 建议观察
- 建议防守
- 暂无信号

## 6. 案例四：欧奈尔 / Minervini

### 6.1 它们是什么

欧奈尔和 Minervini 更接近：

- 成长股筛选体系
- 趋势突破体系
- 质量与强势结合的方法

### 6.2 它们不是什么

它们不是：

- 投资模式
- 单纯价值投资
- 单纯均值回归方法

### 6.3 在 StockWise 中的落位

| 层级 | 映射判断 |
| --- | --- |
| 世界观层 | 中映射 |
| 研究原则层 | 强映射 |
| 量化方法框架 | 很强映射，主要对应成长突破 / 质量成长 |
| 量化规则组件 | 很强映射 |
| 投资模式 | 不直接映射 |

### 6.4 如何进入系统

更适合拆成：

1. 原型
   - 成长突破
   - 质量成长
2. 组件
   - 相对强度
   - 盈利增长
   - 量能扩张
   - 趋势过滤
   - 突破确认

### 6.5 最终产品表达

最终不会出现“欧奈尔模式”，而是：

- 一套成长突破类量化方法框架
- 一组成长股筛选规则组件
- 分析模型可以借用“强势、领涨、放量突破”语言解释

---

## 7. 案例五：网格交易

### 7.1 它是什么

网格交易更像：

- 执行方法
- 仓位管理框架
- 价格带内的战术引擎

### 7.2 它不是什么

网格交易不是：

- 量化模型的状态识别层
- 世界观层
- 投资模式

### 7.3 在 StockWise 中的落位

| 层级 | 映射判断 |
| --- | --- |
| 世界观层 | 弱映射 |
| 研究原则层 | 中映射 |
| 量化方法框架 | 中映射，偏执行框架而非市场识别框架 |
| 量化规则组件 | 中映射 |
| 投资模式 | 不直接映射 |

### 7.4 如何进入系统

网格不适合作为 `Layer-1 / QuantEngine` 的主状态模型。  
它更适合进入：

1. tactics / 执行策略层
2. 某些投资模式下的战术模板
3. 分析模型输出中的执行建议

### 7.5 最终产品表达

如果未来支持网格，它更可能表现为：

- 一类战术执行建议
- 一种仓位管理方法

而不是：

- 一个新的 `NoSetup / Watch / TriggeredLong / RiskOff` 状态来源

---

## 8. 五个案例后的统一结论

从这五个案例可以看出：

### 8.1 不是所有方法都应直接进入“投资模式”

以下内容都不应直接命名为投资模式：

- 巴菲特
- 埃尔德
- 海龟
- 欧奈尔
- Minervini
- 网格交易

投资模式只负责：

- 同一底层事实下的用户动作风格差异

### 8.2 大多数方法应先落在“量化方法框架”或“量化规则组件”

这是最适合工程化、测试、研究和迭代的层。

### 8.3 `Layer-1` 只代表当前量化模型实现

它不是：

- 所有方法的总称
- 所有交易智慧的总容器

它只是当前量化模型的工程实现层。

### 8.4 分析模型的价值不是替代量化模型

分析模型更适合：

- 解释量化状态
- 展开战术建议
- 提供分歧视角

而不是替代量化模型本身。

---

## 9. 一句话版本

**外部世界的方法，先拆成世界观、原则、原型和组件，再进入量化模型；分析模型负责解释，投资模式负责裁决，视图层负责展示。**
