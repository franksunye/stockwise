# 知守 AI (ZISO AI) 领域名词表（用户视角）

定位：MOFU；节奏：Hub。

面向普通投资者，知守 AI (ZISO AI) 让用户添加自选股，持续查看预测结果与分析过程，作为日常投资参考。产品可免费使用；付费后可解锁更多能力，并按个人风格选择不同投资模式。通知是核心互动方式，持续推送关键变化与操作提醒。整体体验像一位专业投研团队在身边服务：既有量化分析与可读报告，也有规律化的投研节奏（如晚间复盘、晨间计划）。我们强调辅助而非替代决策，并通过预测回看与策略迭代，帮助用户形成可持续的投资方法。

MOFU = Middle of Funnel，营销漏斗中段。
意思是：用户已经知道你是谁，正在比较、评估“值不值得长期用”。

Hub = 持续更新的“常规内容”节奏（不是一次性爆款）。
意思是：固定频率输出内容/触达，比如每周复盘、每日提醒、周期性报告。

各类文字定位：

产品层（顶层）：产品定位/价值主张
体验层（你这段）：核心体验叙述（用户是谁、得到什么、如何互动、整体服务感）
场景层：日常盯盘、晚间复盘、晨间计划、提醒触达
用例层：添加自选股、查看预测、阅读报告、切换投资模式、接收通知

## 1) 目的与使用方式

本文件定义 知守 AI (ZISO AI) 面向用户的核心领域实体与命名边界，避免产品、前端、后端、内容运营出现同物多名。

- 用户可见文案以本文件为准。
- 字段命名可保留历史兼容，但前台展示必须映射到本文件术语。
- 新功能评审时，若引入新实体，先补本表再开发。

## 3.1) 核心系统 Lane（跨团队统一叫法）

> 这一节定义的是“系统级数据链路名词”，用于产品、研发、运营讨论时避免把产品口径和研究口径混为一谈。
> 中文主叫法统一使用“生产线 / 实验线”；英文保留 `Production Decision Lane / Research Quant Lane`。

| 中文名 | 英文名 | 定义 | 备注 |
|---|---|---|---|
| 生产线 | Production Decision Lane | 面向用户正式展示的决策数据链路 | 对应 Investment Mode |
| 实验线 | Research Quant Lane | 面向量化研究、参数校准、版本观测的数据链路 | 对应 sidecar / calibration |

补充说明：
- 两条 lane 都建立在真实市场数据之上。
- `Production Decision Lane` 不是“真实成交”，其中模式台账仍是模拟台账。
- `Research Quant Lane` 不是“假数据”，但它不是前台正式展示口径。
- 样本池中文主叫法统一使用“生产池 / 研究池”。

## 3.2) 模型分层（跨团队统一叫法）

> 这一节定义“量化模型 / 分析模型 / 投资模式 / 视图层”的边界，用于承接未来方法扩展。

| 中文名 | 英文名 | 定义 | 备注 |
|---|---|---|---|
| 量化方法框架 | Quant Method Framework | 对外部方法做母类归纳的研究层 | 如趋势跟随、突破、均值回归、网格、价值、配置 |
| 量化规则组件 | Quant Rule Components | 可组合、可测试、可替换的规则零件 | 如 Donchian、ATR、MA filter、volume expansion |
| 量化模型 | Quant Model / Quant Engine | 将规则组件收敛成结构化状态的后台模型 | 当前工程实现对应 `Layer-1 / QuantEngine` |
| 分析模型 | Analysis Model | 负责 AI 判断、解释、战术展开的模型层 | 当前主要对应 LLM |
| 投资模式 | Investment Mode | 面向用户的动作风格层 | 稳健 / 平衡 / 进取 / 仅观察 |
| 视图层 | View Layer | 决定首页、内参、决议页如何展示不同结论 | 不属于模型本身 |

补充说明：
- 海龟、MACD、网格、Triple Screen 不属于“投资模式”。
- 它们应先进入“量化方法框架”或“量化规则组件”。
- `Layer-1` 是当前量化模型的工程实现名，不是未来所有方法体系的总称。

|---|---|

## 5) 命名边界（禁止混用）

- `量化方法框架` 不等于 `投资模式`。
- `量化规则组件` 不等于 `投资模式`。
- `量化模型` 不等于 `分析模型`。
- `策略`（内部工程对象）不等于 `投资模式`（用户产品对象）。
- `Production Decision Lane` 不等于 `Research Quant Lane`。
- `生产线` 不等于 `实验线`。
- `Investment Mode`（产品结果）不等于 `sidecar`（研究结果）。
- `signal`（兼容层）不等于 `action semantics`（用户执行语言）。
- `Layer-1` 是工程实现层名，不应替代“量化模型”作为总概念。
- `看多/看空/观望`、`做多/做空` 属于旧表述，不再作为新 UI 主文案。
- `层状态`可以技术展示，但用户主结论应优先显示动作语义。

## 6) 前后端字段对齐建议

### 6.1 前端展示优先级

1. `layer1_status` -> 四语义
2. 若为空，回退 `signal` -> 四语义兼容映射
3. 再为空，显示 `等待分析`

### 6.2 数据写入要求（后端）

- 新增/更新预测记录时，应写入 `layer1_strategy_version`。
- 线上默认策略版本为 `tradeability_v2`。
- 运营报表按 `layer1_strategy_version` 分层统计，避免跨版本混算。
