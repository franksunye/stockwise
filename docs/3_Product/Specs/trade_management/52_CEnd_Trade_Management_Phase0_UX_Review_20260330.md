# C 端交易管理 Phase 0 UX 审视

日期：2026-03-30  
范围：`TacticalBriefDrawer` 第三个页签 `管理` 的第一版 UX 审视  
目标：以极高标准审视一个“极简但真实可用”的第一版管理模块，判断它是否已经具备产品级说服力，以及下一步应如何收敛。

---

## 1. 结论

当前版本已经具备：

- 功能闭环：录入持仓 -> 查看建议 -> 记录已执行
- 路径闭环：在 dashboard 单票上下文内完成，不跳出主心智
- 工程闭环：独立数据面、局部缓存、无主链路污染

但当前版本**还不能算是高完成度 UX**。

它更像：

- 一个已经跑通的产品原型
- 一个克制的 Phase 0 功能页

而不是：

- 一个已经完全融入 `内参 / 决议` 体系的成熟第三页签

一句话判断：

**当前版本“可用且正确”，但还不够“高级、统一、自然”。下一步应以 UX 收敛为主，而不是继续扩功能。**

---

## 2. 当前版本的优点

### 2.1 入口正确

`管理` 放在 `TacticalBriefDrawer` 内，而不是另起全局页面，这一点是正确的。  
它延续了 dashboard 的单票心智，没有把用户从“正在看这只票”拉去“处理整个持仓系统”。

### 2.2 功能边界克制

第一版只做：

- 仓位摘要
- 今日建议
- 详情展开
- 最小执行核销

没有过早引入历史列表、复杂工作台、组合视角。  
这符合极简第一版的原则。

### 2.3 闭环真实

`已执行` 不是假按钮，而是真实事件写入。  
这使得 `管理` 不是“建议展示层”，而是“最小执行层”。

### 2.4 不破坏现有择时体验

`内参 / 决议` 没有被改坏。  
`管理` 的加入是 sidecar，而不是重写 Tactical 体系。

---

## 3. 当前版本的核心问题

### 3.1 还不像同一个视觉系统里长出来的页面

这是当前最大问题。

虽然 `管理` 已经使用了相近的按钮、圆角、颜色和抽屉骨架，但它的信息展示方式仍然更像：

- 功能卡片页
- 数据面板页

而 `内参` 是：

- 单票叙事页
- 结论驱动页
- 已被打磨过的内容阅读体验

所以用户会感到：

- `内参` 是“看判断”
- `管理` 是“看功能”

这会削弱三页签的一体感。

### 3.2 首屏没有绝对主结论

当前 `管理` 首屏是多块卡片并列：

- 仓位摘要
- 今日建议
- 轻量操作

信息都对，但没有一个真正的“第一眼中心”。  
而 `内参` 的优点恰恰在于：用户一眼就知道“今天最重要的结论是什么”。

`管理` 也应该有类似的主导信息：

- 当前状态
- 今日动作
- 一句话纪律线

这三者应先于其他字段。

### 3.3 表达仍偏字段化

例如：

- 成本价
- 建仓日
- 最近动作
- 下次观察
- 更新时间

这些都该保留，但当前呈现方式还偏“属性面板”。  
缺少一点 `内参` 那种“判断先行、数据辅助”的节奏。

### 3.4 “建议依据”还是功能实现视角，不是阅读体验视角

当前 `建议依据` 虽然已经从原始 markdown 改成了更干净的文本块，但仍偏“内容容器”。  
它还不是一个被 UX 设计过的阅读模块。

问题在于：

- 用户看到的是一段整理过的说明
- 不是被结构化过的执行逻辑

理想状态下，它应更像：

- 当前判断
- 执行原则
- 关键观察位
- 纪律线说明

而不是“卡片原文摘录”。

### 3.5 无持仓态仍偏 onboarding，而非自然嵌入

无持仓态当前是正确的，但略显“功能入口化”。  
它完成了闭环，却还没做到“安静地嵌入 Tactical 系统”。

它需要更像：

- 一个轻提示
- 一个自然的下一步

而不是：

- 一个新能力 onboarding 卡

### 3.6 录入与核销抽屉已统一交互骨架，但还没有强烈的“产品感”

当前两个抽屉：

- 结构已经和 `UserCenterDrawer`、自选池输入区更接近
- 操作也足够轻

但还需要继续收口：

- 表单字段文案
- 说明语句长度
- 强弱按钮关系
- 用户视角语言

它们现在是“正确的表单”，但还不是“有完成度的产品交互”。

---

## 4. 理想的一版管理页，应长成什么样

### 4.1 不是更多功能，而是更清晰的主次关系

理想的一版 `管理` 不需要更多东西，只需要把已有内容排出更好的阅读顺序：

1. 主结论
2. 仓位上下文
3. 执行记录
4. 展开说明

### 4.2 首屏需要一张“管理主卡”

这张主卡应承担 `内参` 主卡的角色。  
建议内容：

- 状态：如 `盈利保护`
- 今日动作：如 `继续持有，不追高`
- 一句话纪律线
- 次级信息：下次观察日

这张卡应该成为用户第一眼看到的中心。

### 4.3 仓位信息应退到辅助层

仓位信息很重要，但不是首页第一结论。  
建议：

- 保留仓位、成本、建仓日、最近动作
- 但放在主卡之后
- 作为“为什么这条建议对我成立”的上下文

### 4.4 执行动作应更像“轻闭环”，而不是“录表”

`已执行` 是必要的，但它不应让用户觉得自己在做后台录入。  
它应该让人感觉是在：

- 给这笔仓打一个执行回执
- 而不是在维护交易账本

### 4.5 详情展开要像 `内参` 的后半段，而不是折叠说明

更理想的结构是：

- 判断依据
- 执行方式
- 关键观察位
- 最近执行

而不是单纯“展开更多文字”。

---

## 5. 与现有系统的一致性原则

### 5.1 与 `内参 / 决议` 一致

应保持一致的部分：

- 顶部页签语言
- 卡片密度
- 节标题风格
- 首屏结论优先
- 单票上下文感

不必强行一致的部分：

- `内参` 的情景卡 carousel
- `决议` 的多顾问列表

原因：`管理` 的任务是执行，不是分析比对。

### 5.2 与自选池一致

应复用自选池已经成熟的部分：

- 主次按钮关系
- 输入框样式
- 搜索/录入时的极简提示语言
- 空态要安静，不要大声

### 5.3 与个人中心一致

应复用个人中心已经成熟的部分：

- 底部抽屉骨架
- 顶部标题/关闭关系
- 表单区 + 底部操作区的布局
- 滚动区与固定操作区的分离

---

## 6. 下一步建议

### 建议方向

下一步不建议继续加功能。  
建议只做一轮 **UX 收敛**：

1. 重排 `管理` 首屏信息层级
2. 做出真正的“管理主卡”
3. 把 `建议依据` 改成结构化阅读模块
4. 收窄无持仓态的 onboarding 感
5. 继续压平录入与核销抽屉的表单感

### 不建议现在做的事

- 不建议新增更多字段
- 不建议加入完整历史列表
- 不建议加入组合/总览能力
- 不建议新开详情页
- 不建议做更复杂的状态机可视化

这些都会稀释当前最重要的事情：

**让 `管理` 真正像 `TacticalBriefDrawer` 的第三个成熟页签，而不是一个正确但陌生的功能页。**

---

## 7. 最终判断

当前版本值得继续，不需要推翻。

但下一步的工作重心应明确从：

- “把功能补齐”

转成：

- “把体验收成熟”

标准不是“能用就行”，而是：

**让用户觉得这个页签本来就应该在这里，而且它和 `内参 / 决议` 属于同一个被精心设计过的系统。**
